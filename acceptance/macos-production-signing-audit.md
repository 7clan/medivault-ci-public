# MediVault macOS — Production Signing Audit (shipped component inventory)

Status: **AUTHORED** (production-readiness phase) — the structural half is
CI-verified by the `production-readiness` mode; the Developer-ID half
activates when Apple credentials arrive.

Scope: the ACTUAL shipped `MediVault.app`, audited recursively from the
frozen staging contract (`macos/scripts/stage-pg-bundle.sh`,
`stage-app-bundle.sh`, `build-dmg.sh`) plus the production-readiness
additions (`medivault-launchagent` helper).

Signing strategy: **inside-out, explicit, per component** — never
`codesign --deep` (Apple TN2206 and the Tauri issue tracker both document
that `--deep` signs in an unreliable order and misses non-standard Mach-O
locations; our Node/PG/prisma binaries live in exactly such locations).
The deterministic order and entitlements are generated by
`macos/scripts/signing-manifest.sh` (depth-descending = deepest first,
then the `.app` root last) and applied by `macos/scripts/sign-production.sh`.

## 2. Hardened Runtime entitlement plan — least privilege

All components are signed with `codesign --options runtime` (Hardened
Runtime) — required for Developer ID distribution + notarization.

Entitlement policy (each grant has a written justification; the CI proof
is empirical, strictest-first):

| Component | Proposed production entitlements | Justification |
|---|---|---|
| Node runtime (row 4) | `com.apple.security.cs.allow-jit` (ONLY if the strictest-first CI proof shows V8 crashing without it) | V8 JIT-compiles JS; under Hardened Runtime, MAP_JIT pages without the entitlement crash on JIT tier-up. Apple's entitlement doc names this exact use case. The production-readiness CI mode runs a JIT-tiering workload under the strictest config first: if it passes, ZERO entitlements ship; if it crashes, the failure is recorded and ONLY the Node binary gets allow-jit. |
| EVERYTHING else (rows 1–3, 5–14, the `.app` root, the DMG) | **NONE** | No JIT, no unsigned-memory use, no dyld environment manipulation, no debugging. Pure C/Rust/Swift-System-framework code. |

**Explicitly NOT granted anywhere** (directive + Apple least-privilege):
`disable-library-validation` (all nested code is ours or Apple-linked —
validation stays enforced), `allow-unsigned-executable-memory` (broad
exception; Node uses MAP_JIT, so the narrow allow-jit suffices if needed),
`disable-executable-page-protection` (never), `get-task-allow`
(debug-only, never in distribution).

## 3. Current signature state (pre-credentials)

Today every component ships **ad-hoc signed** (CI phase): identity `-`,
no secure timestamp, entitlements none, Hardened Runtime NOT yet applied
by the frozen pipeline. The production-readiness CI mode adds the
STRUCTURAL proof: ad-hoc + `--options runtime` + entitlements in the exact
production inside-out order, verified by
`macos/scripts/verify-signatures.sh` — this is explicitly **not**
production signing and never claims Gatekeeper acceptance.

## 5. Relocatability + path hygiene (audited, fixed in this phase)

* The LaunchAgent plist now uses **`BundleProgram`** with the
  bundle-relative supervisor path (launchd.plist(5): the SMAppService-only
  key). The previous absolute `/Applications/...` `Program` key is GONE
  (it broke per-user `~/Applications` installs and embedded a
  machine-location assumption).
* The shipped `supervisor-config.json` is now fully RELOCATABLE: every
  bundle path `Contents/`-relative, user dirs absent (per-user `~/Library`
  defaults applied by the supervisor at load). Previously the shipped
  config embedded CI-runner staging paths (Stage 6/7 papered over this by
  re-pointing post-install — an impossible step for a real user).
* No Homebrew, no `/opt/homebrew`, no `/usr/local`, no build-machine
  absolute paths anywhere in the shipped tree (macho-gate §3/§4 +
  config-content assert).
